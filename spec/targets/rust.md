# Target: `rust` (server and client)

Status: normative for the built-in Rust generator. It follows `spec/targets/typescript.md` and `spec/targets/java.md` semantically: the same contract gives the same wire behaviour, the same errors with the same signatures, and the same canonical bytes. One implementation of models and runtime serves both roles.

## 0. Hard rules
- **Rust 1.75 or newer** (`async fn` and `impl Future` in traits). The generated crate declares `edition = "2021"` and `rust-version = "1.75"`, builds with zero warnings and passes `cargo clippy -- -D warnings`.
- **One core dependency decision: `serde` and `serde_json`.** Rust has no JSON in `std`. The two alternatives were an embedded JSON codec (as the Java target does) or the de-facto standard. The generator takes the standard: derive-based models are what a Rust developer expects (`#[derive(Serialize, Deserialize)]`, usable with any serde format and any framework), it avoids shipping and maintaining a second JSON parser in every crate, and `serde_json::Value` is the natural type of the contract's `json` scalar. The cost is two dependencies instead of zero; they are the only dependencies of the core. Everything else (the router, validation, canonical bytes, the regex engine for `@pattern`) is embedded in the crate (`src/veld/`), so there is no `regex`, no `chrono`, no `uuid`, no `base64`, no `thiserror`.
- **Only the chosen framework is a dependency.** A server adds `axum` (`framework = "axum"`, the default). A client adds `reqwest` plus `tokio` (the `time` feature, for reconnect backoff) or `ureq` (`framework = "ureq"`). `futures-core` (the `Stream` trait, nothing else) is added only when the contract has streams; `tokio-tungstenite` and `futures-util` only for a `reqwest` client of a contract with `ws` endpoints. A server with `ws` endpoints enables axum's `ws` feature and `tokio`'s `time`.
- **Identity by signature, never by type.** Every model, enum, union and error has `const VELD_SIG`, equal to the IR signature verbatim (`spec/ir.md` §5.1). Two copies of a declaration generated into different crates are different Rust types; `same` compares signature, operation and canonical bytes.
- **Unsupported is loud.** The one limit is `E0801` for a client of a contract with `ws` endpoints on the blocking `ureq` transport (it has no WebSocket client). Nothing wrong is emitted.
- Every Rust file starts with `// Code generated by veld. DO NOT EDIT.`. Output is deterministic (sorted maps, no timestamps, no absolute paths). Generated code is not rustfmt-formatted: run `cargo fmt` over it if you want, the manifest keeps a hash of what Veld wrote.

## 1. Options and layout

Options (`[targets.options]`, validated, unknown keys are `E0802`):

| Option | Default | Meaning |
|---|---|---|
| `crate-name` | `<package of the first service>-<role>` | The name in `Cargo.toml`. Letters, digits, `-` and `_`, starting with a letter, else `E0802`. |
| `transport` | `reqwest` | The HTTP transport of the clients that a **server** contains for its `consumes`: `reqwest`, `ureq` or `none` (bring your own `Transport`). Anything else is `E0802`. |
| `validate` | `true` | `false` skips run-time **request** validation by default (the types are unchanged): the client's `ClientOptions` default to no validation (`validate(true)` turns it back on) and the generated hooks' `validate_requests()` returns `false`. Responses are validated only when `validate_responses()` is `true`. |

`framework` (server): `axum` (default). `framework` (client): `reqwest` (default) or `ureq`. Any other value, or a framework on a role that takes none, is `E0803` and the message lists the valid values. `actix-web` is not provided: a server framework is an adapter over the runtime's `Handler` (§5), and writing one for another framework is a few dozen lines against `Handler::invoke` and `Handler::ws`.

The output is a complete crate:

```
Cargo.toml                         dependencies: serde, serde_json, the chosen framework(s)
README.md
src/lib.rs                         module list; allows a few clippy lints that suit generated code
src/veld/                          the runtime (identical bytes in both roles where shared)
  canonical.rs  RFC 8785 JSON, ECMAScript number formatting
  error.rs      Error, Problem, Issue, VeldDecl, VeldValue, DeclaredError, same, Identity
  schema.rs     Schema, validation, defaults, the wire mapping, canonical bytes
  regex.rs      the @pattern engine (language.md §7.1)
  spec.rs       EndpointSpec and friends (static data)
  page.rs  util.rs  mod.rs
  server.rs     the core: router, auth, middleware, binding, error mapping, SSE, WebSocket   (server role)
  client.rs     ClientOptions, Transport, Core, SSE streams, WsChannel                       (client role, or a server with `consumes`)
  stream.rs     BoxStream, unfold, SseEvent, SSE framing and parser                          (streams only)
  transport_reqwest.rs | transport_ureq.rs                                                    (by framework)
src/prelude.rs                     prelude errors: NotFound, Internal, Unauthorized, ValidationError, ...
src/<package>/mod.rs               the modules of a contract package
src/<package>/<module>.rs          models, enums, unions, errors and constants of one contract module
src/<package>/<service>_client.rs  <Service>Client<T>, request structs, ENDPOINTS         (client role)
src/<package>/<service>_server.rs  <Service>Service, <Service>Hooks, <Service>Handler      (server role)
src/adapters/axum.rs               router(handler)                                          (server role)
src/clients/<service>/...          a self-contained client tree for each consumed service   (server role)
```
Package, module and service names become snake_case module names (`.` and `/` become `_`). Names that would clash with the crate's own modules (`veld`, `prelude`, `adapters`, `clients`, `std`, ...) get a trailing `_`.

## 2. Type mapping

| Veld | Rust | Wire |
|---|---|---|
| `string` | `String` | string |
| `int` / `long` / `float` / `bool` | `i32` / `i64` / `f64` / `bool` | number; **`long` is a decimal string** |
| `decimal` | `String` (the text is significant: `1.50` is not `1.5`) | string |
| `date` / `time` / `datetime` / `uuid` | `String` (validated by the schema; canonical form is UTC `Z` / lower case) | string |
| `bytes` | `Vec<u8>` | base64 string |
| `json` | `serde_json::Value` | any JSON |
| `T[]`, `Map<string, T>` | `Vec<T>`, `std::collections::BTreeMap<String, T>` | array, object |
| `Page<T>` | `veld::Page<T>` (`items`, `total: i64`, `page`, `size`) | `{items,total,page,size}` |
| `model` | `struct`, fields in `snake_case` with `#[serde(rename = "wire")]` where the wire name differs; reserved words are raw identifiers (`r#type`, `self` becomes `self_`) | object |
| `enum` | `enum`, variants in `PascalCase`, `#[serde(rename = "WIRE")]`, `wire()` gives the contract value | string |
| `union` | `enum` with one newtype variant per arm and `#[serde(tag = "<discriminator>")]` | object with the discriminator field |
| `error` | like a model, plus `DeclaredError`, `From<E> for veld::Error`, `Display` and `std::error::Error` | problem+json |
| `const` | `pub const NAME: i32 = 50;` (strings as `&str`); constants of other types are `E0801` | n/a |

`datetime`, `date`, `time`, `uuid` and `decimal` are `String` so that the generated crate needs no `chrono`, `time`, `uuid` or `decimal` dependency; the schema validates them and canonical bytes normalise them. Optional fields are `Option<T>` (absent on the wire, never `null`). A recursive reference is boxed. Defaults are applied by the schema when a value is decoded (`T::from_wire`, the server's binding, the client's response decoding) and when canonical bytes are computed; `readonly` fields are dropped from request bodies. A declaration named like an item of the standard prelude (`Option`, `Result`, `String`, ...) gets a trailing `_`. `#[deprecated]` is never emitted (the generated code itself uses every item); the deprecation is written into the docs.

The *typed form* (what `serde` derives produce: `long` as a number, `bytes` as an array) and the *wire form* (what travels) differ only in those two scalars. `VeldDecl::to_wire` and `from_wire` convert, applying defaults; `serde_json::to_string(&value)` is the typed form, not the wire form.

## 3. Identity, equality and canonical bytes

```rust
pub trait VeldDecl: Serialize + DeserializeOwned {
    const VELD_SIG: &'static str;
    fn schema() -> &'static Schema;
    fn to_wire(&self) -> Value;                       // wire form, defaults applied
    fn from_wire(wire: &Value) -> Result<Self, Error>;
    fn validate(wire: &Value) -> Vec<Issue>;
}
pub trait VeldValue {                                  // implemented for every VeldDecl and for veld::Error
    fn veld_sig(&self) -> &str;
    fn veld_op(&self) -> Option<&str> { None }
    fn canonical(&self) -> Vec<u8>;                    // RFC 8785, defaults applied, UTC datetimes, lower case uuids
}
pub fn same(a: &dyn VeldValue, b: &dyn VeldValue) -> bool;
```
(`veld_sig` returns `&str`, not `&'static str`: a decoded `Error` carries a signature that it read from the wire.)

- `same(a, b)` is true when both have a signature, the signatures are equal, the operation signatures are equal (errors; a value that is not an error has none) and the canonical bytes are equal. It never compares types. Two different declarations with identical fields are never the same. An error without a signature (`Error::Http`, `Error::Transport`, `Error::Other`) is never the same as anything. `same_all` compares slices element by element.
- **Across crates** every generated crate has its own `VeldValue` trait. Build `veld::Identity::of(&value)` in each crate (plain data: `sig`, `op`, `canonical`) and compare with `veld::same_parts(&a, &b)`; the fields are public, so an identity of one crate converts to the other's.
- `DeclaredError::matches(&err)` is true for this declaration from any operation; `matches_service(&err, "orders/Orders")` also fixes the service of the operation; `from_error(&err)` returns the typed value.
- Canonical bytes of a model, union or enum are `canonical(&value)` of its wire form after decoding (`spec/ir.md` §5.3) and equal the goldens in `tests/wire/`.

## 4. Errors

```rust
pub enum Error {
    Problem(Problem),          // a declared error: sig, title, status, op, data (wire form, defaults applied)
    Invalid(Vec<Issue>),       // a request that could not be decoded (validation off); answered as ValidationError
    Http { status: u16, body: String },  // a non-2xx response that is not a declared problem
    Transport(String),         // the network failed or a body was unreadable
    Other(String),             // anything else; on a server it becomes Internal without its message
}
```
- Service methods return `Result<T, veld::Error>`. `Err(OutOfStock { sku }.into())` (or `.into_error()`) is a declared error.
- **Server behaviour:** an error whose `sig` is declared for the endpoint is answered as problem+json at the declared status with `operation` set. Anything else, including an undeclared declared-looking error, becomes `500 Internal` with empty data; the original goes to the `on_error` hook.
- **Client behaviour:** a problem+json `type` that is a declared error of the endpoint is `Error::Problem` with `op` and `status` set; recover the value with `OutOfStock::from_error(&err)`. A problem with an unknown `type` and any other non-2xx response is `Error::Http`. A network failure or an unreadable body is `Error::Transport`.
- Problem+json members are written in the order `type`, `title`, `status`, `operation`, `data`.

## 5. Server

```rust
pub trait OrdersService: Send + Sync + 'static {
    fn get_order(&self, request: GetOrderRequest, ctx: &RequestContext)
        -> impl Future<Output = Result<Order, veld::Error>> + Send;   // implement with `async fn`
}
pub trait OrdersHooks: Send + Sync + 'static {
    fn auth_bearer<'a>(&'a self, token: &'a str, ctx: &'a RequestContext) -> impl Future<Output = Option<Principal>> + Send + 'a;
    fn middleware_rate_limit<'a>(&'a self, ctx: &'a RequestContext) -> impl Future<Output = Result<(), veld::Error>> + Send + 'a;
    fn on_error(&self, err: &veld::Error, ctx: &RequestContext) {}
    fn validate_requests(&self) -> bool { true }   // false with `validate = false`
    fn validate_responses(&self) -> bool { false }
}
let handler = OrdersHandler::create(service, hooks);   // or OrdersHandler::plain(service) when no hooks are needed
let app = axum::Router::new().merge(adapters::axum::router(handler));
```
- The hooks trait has exactly the hooks the endpoints need (`auth_bearer`, `auth_basic`, `auth_api_key`, `middleware_<name>`) as required methods, so a missing hook is a compile error. A service that needs none gets `plain(service)` and a `NoHooks` type.
- One request struct per endpoint holds the path, query, header and body parameters by name (the `ws` stream body is not part of it).
- `veld::server::Handler` is the framework-agnostic core: `handle(Request) -> Option<Response>` (`None`: no route), `invoke(name, Request)` (one named endpoint through the same pipeline, for frameworks that route themselves) and `ws(Request) -> Option<WsConversation>`. Routing is exact on literal segments with parameters extracted; a trailing slash is ignored; HEAD is not implicit; literal routes win over parameterised ones.
- Pipeline: match, auth (`401 Unauthorized`), middleware in declared order, bind and validate path, query, headers and body (`422 ValidationError` with `issues`), call the implementation, optionally validate the response, serialise with the declared success status. `RequestContext` has `method`, `path`, `headers` (lower case names), `header(name)` and `principal::<T>()`.
- **axum adapter** (`adapters::axum::router(handler) -> Router`): one route per endpoint at its real path (`{id}` parameters), plus the trailing-slash variant, built on `Handler::invoke`; merge it into your application. The status codes and bodies are exactly the core's.

## 6. Client

```rust
let client = OrdersClient::reqwest(ClientOptions::new().base_url("https://api.example.com").bearer(|| token()))?;
let order = client.get_order(GetOrderRequest { id }).await?;
```
- `<Service>Client<T: Transport>` is **generic over the HTTP stack**: `veld::client::Transport` is two async functions (`send`, and for streams `open` and `sleep`; `connect_ws` for WebSockets). Implement it for the HTTP library you already use and call `OrdersClient::new(transport, options)`. The generated crate includes a ready-made adapter as its framework: `reqwest` (`ReqwestTransport::with_client(your_client)` shares your pool) or `ureq` (blocking: its futures complete without waiting, drive them with `veld::block_on`).
- `ClientOptions` has `base_url`, `header`, `header_supplier`, `bearer`, `basic`, `api_key`, `validate`, `timeout` (default 30 s) and `reconnect`.
- **Base URL resolution:** the `base_url` option, else the environment variable `VELD_<SERVICE>_URL` (service name upper-snake), else the contract's `base-url`, else `Error::Transport` from the constructor.
- Path parameters are percent-encoded; query objects use repeated keys for lists, keys are sorted, absent optionals are omitted.
- With validation on, the request is validated first and a `ValidationError` with `op` set is returned locally (no request is sent). Responses are decoded, not validated.
- A method without parameters takes no argument; one without a response body returns `Result<(), Error>`.

## 7. Streaming: Server-Sent Events and WebSocket

The wire behaviour is the TypeScript target's, byte for byte (`spec/targets/typescript.md` §4b, `tests/wire/streaming/sse.json`).

**SSE** (`get ... -> stream T`). The server method returns `Result<veld::stream::EventStream<T>, veld::Error>`, where `EventStream<T>` is `Pin<Box<dyn Stream<Item = Result<SseEvent<T>, Error>> + Send>>` and `SseEvent::of(item).event("tick").id("7").retry(1500)` sets the optional fields. The first item is pulled before the status is sent: an error before the first event is a normal problem+json response; after that it is a final `event: error` frame and the stream ends. The server **drops the stream** when the client goes away, so `Drop` is where an implementation cleans up. The client method returns `Result<BoxStream<Result<T, Error>>, Error>`: the HTTP call is eager (a non-2xx response is the error of the method), later errors are the stream's last item, `<name>_with(request, SseOptions)` resumes (`SseOptions::resume_after(id)` sends `Last-Event-ID`) and reports ids (`on_event_id`). Drop the stream to cancel. `veld::stream::{unfold, iter, next}` build and read streams without another dependency.

**WebSocket** (`ws "/path" name(params, body: stream In) -> stream Out`). Frames are text. Server to client: `{"data":<canonical JSON>}` or the final `{"error":<problem JSON>}` followed by a close; client to server: the bare canonical JSON. Close codes: `1008` for declared errors, validation and auth, `1011` for `Internal`, `1000` for a normal end, `1003` for a binary frame. The server method receives a `WsSession<In, Out>` (`()` marks a side with no messages): `recv().await -> Option<Result<In, Error>>` (validated; `?` on an `Err` ends the conversation with a `ValidationError` frame whose issue paths start with `message`), `send(Out)`, `close()`; returning `Ok(())` closes with 1000. Auth uses the same hooks as HTTP, from headers or, when absent, `?access_token=` (bearer) and `?api_key=`. `@header` parameters are also read from the query string. A failed auth is answered after the upgrade (problem frame, then close). A path that is not a `ws` endpoint is not routed, so the **axum adapter refuses the handshake with `404`** (it has no socket to close with `4404`). The conversation future is dropped when the client goes away. The client method returns `Result<WsChannel<T, In, Out>, Error>` connected: `send(Out)` (validated, local `ValidationError`), `recv() -> Option<Result<In, Error>>` (`None` after a normal end or `close()`), `close()`. `wss://` needs a TLS feature of `tokio-tungstenite` that the generated crate does not enable.

**Reconnect** (`ClientOptions::reconnect(Reconnect { initial_ms, max_ms, retries })`, or per call). Off by default; defaults 1000 ms doubling to 30000 ms, 10 consecutive failures. Only connection failures are retried; a typed error, an error frame or event, a normal end and a dropped channel never reconnect. SSE reopens the request with `Last-Event-ID` set to the last event id delivered, so the stream is continuous. A `WsChannel` reconnects inside `recv()` (a new socket and a new conversation on the server), queues what `send` is given while the connection is down and sends it after the reconnect; a message already written to the broken socket is lost. When the attempts run out the last `Error::Transport` is returned.

Every Rust target writes `README.md` at the root of its crate: the layout, how to use the server or client, the `same` note and how to regenerate. It is deterministic.

## 10. Invariants (`spec/rules.md`)

Supported: `rules_invariants`. The endpoint, state-machine and policy rules (`rules_endpoint`, `rules_transitions`, `rules_policies`) are still `E0801`. Partial checks (`spec/rules.md` §5.4) are TypeScript only. A crate has the rules runtime when any declaration it emits has a rule; otherwise every generated byte is exactly what it was before rules existed (the runtime files carry their rule hooks in `// #if rules` regions that are removed for such a crate).

- **Runtime.** `src/veld/rules/mod.rs` is the thin layer; `decimal.rs`, `instant.rs`, `num.rs` and `text.rs` next to it are the helper files of the reference evaluator (`crates/veld-rules/src/helpers`), embedded byte for byte, so generated code and the oracle run the same helper source. `rules::Violation` is the object of §7 (`to_text` writes `rule`, `path`, `fields`, `message`, `error` in that order). Evaluation errors are `Result`s (`rules::Fail`, `Res<T>`); generated code propagates them with `?` and never panics. A proven-present optional is read with `rules::some`, a decimal or instant is parsed with `rules::dec` and friends; text that is not one, or an absent "proven present" value, is `Fail::Input`. Validation rules both out, so it cannot happen on a validated value. The rule fails closed with `error: "invalid_value"`, the one `error` value outside §3.7.
- **Printer.** `crates/emitters/rust/src/rules.rs` implements `veld_codegen::ExprPrinter`. A rule is one closure returning `rules::Res<bool>`: `&&`, `||` and `implies` stay lazy, helper calls end in `?`, comprehensions are `rules::all|any|count|sum_*` over a list converted element by element (`rules::list`). Values are `bool`, `i32`, `i64`, `f64`, `Decimal`, `&str` (also uuid), `i64` (datetime and date in epoch milliseconds and days, time and duration in milliseconds) and the enum itself. `==` and ordering use the converted values (decimals by `compare`, uuids case-insensitively), never the raw strings. Anything the printer cannot express is `E0801`.
- **Per declaration with rules**: `RULE_<NAME>` constants (the rule ids, inherited rules included), `check()` (full) and `check_request()` returning `Vec<veld::rules::Violation>` for the value and everything inside it, and `impl veld::rules::Invariants` whose `check_rules` evaluates the declaration's own rules in list order on one typed value. `check_rules` carries an `#[allow]` for the lints that user expressions trip (`a >= 1 && a <= 10`, redundant comparisons).
- **Nesting through the schema.** The schema walk of the runtime works on JSON, the check functions on typed values. The bridge is one function pointer: `ModelSchema.invariants: Option<fn(&Value, Mode, &str, &mut Vec<Violation>)>`, `Some(veld::rules::run::<T>)` for a declaration with rules. `rules::check_wire(schema, wire, path, mode)` converts the wire value once with `Schema::from_wire` (defaults applied, `long` and `bytes` typed), then `walk` visits it in the order and with the path syntax of validation (`$`, `$.rows[1]`, `$.named.k`, `body.items[2]`, `.items` of a page, the arm of a union): an object's own rules first (`run::<T>` reads that one object with serde and calls `check_rules`), then its fields in declaration order. There is one walk, shared by `check()`, the vector driver, the client and the server. The cost is one extra serde read per object that has rules (depth times size), the price of keeping rules on typed values.
- **Request position.** A request body has no `@readonly` fields, but the generated struct needs them. In request mode `check_wire` first fills each absent required read-only field with a placeholder of the right shape; every rule that reads such a field is skipped, so no evaluated rule sees one.
- **Errors.** `veld::Problem` gains `rulings: Option<Box<Rulings>>` (boxed so `veld::Error` stays small; the crate's `lib.rs` allows `clippy::result_large_err`). `Error::violations()` (empty when the problem document has no `violations` member) and `Error::is_local()` expose them; `problem+json` is written with a `violations` member after `data` when there are any. The typed `ValidationError` of the prelude keeps its declared shape (`issues`), so its signature does not change; read the rest from the `veld::Error`.
- **Client.** `ClientOptions::check_rules(false)` turns the local check off (default on). Before sending, a body or `query` object that passed validation is checked in request mode; on a violation nothing is sent and the call returns the `ValidationError` problem (`status` 422, `op` set) with one issue per violation (`code` `rule`, or `rule_error` for an evaluation error), the violations, and `is_local()` true. A response with a `violations` member is decoded into the same fields (`is_local()` false). A local shape-validation failure is `is_local()` too.
- **Server.** Step 5 (bound `body` and `query` object, after shape validation of that parameter) answers `422 ValidationError` with `data.issues` and the top-level `violations`. Step 8 (the success value of an HTTP endpoint) follows `Hooks::rules_output()`: `RuleOutput::Strict` (default; `500 Internal`, no rule detail), `Audit` (sent unchanged) or `Off`; unless `Off`, the result's shape is validated first and a malformed result is `500 Internal`. `Hooks::on_rule_violation(&RuleEvent)` receives `rule`, `operation`, `position` (`Input` | `Output`), `outcome` (`Rejected` | `Audited`), `violation` and `elapsed_micros` (of the check). A mode other than `Strict` is printed once to stderr when `Handler::new` runs. The axum adapter goes through the same core.
- **Not covered.** Items of `stream` endpoints (SSE and WebSocket messages), and invariants of `error` declarations when the server encodes an error or a client decodes one (`spec/rules.md` §5.2): the check functions exist for errors, but the pipeline does not call them.
- **Tests.** `crates/emitters/rust/src/rules/tests.rs` (exact printer output for every expression kind and operand type), `tests/rules.rs` (the 101 non-partial vectors of `tests/rules/core` through generated crates and a generated driver, plus `cargo clippy -D warnings` on them), `tests/rules_http.rs` (a snapshot of the bookings contract and the HTTP round trip of `tests/toolchain/rust/rules-harness`).
