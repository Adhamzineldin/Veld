## What wasted time on Windows, so that it is not repeated

Measured on 26 Nov, at the owner's request:

- **Antivirus.** The agents' build folders were on a path the antivirus scans in real time. It used 25 CPU-hours in 14 hours of uptime, more than any other process. On Fedora this does not exist; on Windows, build only under a path that is excluded from scanning.
- **The same test suite, run again and again.** Each agent ran the whole workspace suite two or three times (30 to 40 minutes each on that machine), the main session ran it again after merging, and CI ran it a third time. Under the new rule it runs once at the end.
- **Too few agents.** For most of 25 Nov only one agent ran at a time, out of caution about memory that a wrong reading caused ("free" memory was read instead of "available": 16 GB were available when 5.5 GB looked free). Build threads were also capped at 4 per agent on a 24-core machine.
- **Agents stopped twice by the app**, not by the owner, each time losing in-flight work until it was saved on a branch.
