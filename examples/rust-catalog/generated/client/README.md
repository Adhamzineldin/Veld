## Layout

- `src/veld/`: the runtime (schemas and validation, canonical bytes, identity, problem+json).
- `src/prelude.rs`: the prelude errors (`NotFound`, `Internal`, `ValidationError`, ...).
- `src/<package>/<module>.rs`: models, enums, unions, errors and constants of the contract.
- `src/<package>/<service>_client.rs`: `<Service>Client<T>`, generic over `veld::client::Transport`.

## Use

`<Service>Client::ureq(options)` builds a blocking client on `ureq`; drive its futures with `veld::block_on`.
Any other HTTP stack: implement `veld::client::Transport` and use `<Service>Client::new(transport, options)`.

## Runtime config

`runtime_config::ClientRuntime` holds what a deployment chooses: the URL of each service the target calls and, for a server with rules, `rules.output`. Fill it from any `serde` source, or with `from_value`, `from_map` (paths such as `services.iam.url`) or `from_env` (the names of the variables are yours). `check` reports every problem at once. The generated code reads no environment variable of its own.

## Identity

`veld::same(&a, &b)` is true when the declaration signatures, the operation signatures (errors) and the
canonical bytes are equal. Two different declarations with identical fields are never the same. Across
crates use `veld::Identity::of(&a)` and compare the plain data (`veld::same_parts`).
