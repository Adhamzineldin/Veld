# Veld for JetBrains IDEs

A thin client for the Veld 2.0 language server. Every language feature comes from `veld lsp`, the
same engine as the VS Code extension (`editors/vscode`). The plugin itself contains no lexer, parser
or analysis.

It works in IntelliJ IDEA, RustRover, WebStorm and the other 2024.3+ IDEs.

| Feature | From |
|---|---|
| Diagnostics, hover, go to definition, references, completion, rename, formatting, semantic tokens | `veld lsp`, through [LSP4IJ](https://github.com/redhat-developer/lsp4ij) |
| Syntax highlighting | The TextMate grammar generated by `cargo xtask codegen` (`src/main/resources/textmate/veld`) |
| `.veld` file type and icon | The plugin |
| Run actions, New Veld File templates, `veld.toml` schema | The plugin (see below) |

The v1 Kotlin PSI plugin (Veld 1.x language) was removed. It is preserved in git history.

## Requirements

- The `veld` binary (`cargo build -p veld --release`), on PATH or set in Settings.
- The LSP4IJ plugin. The IDE installs it with this plugin because it is a declared dependency.

## Tools | Veld actions

Every action runs the `veld` CLI (the path from Settings | Tools | Veld) in a run console in the
Run tool window, in the nearest folder at or above the current file that has a `veld.toml`
(else the project root). All editors are saved first. The console has the usual rerun and stop buttons.

| Action | Runs |
|---|---|
| Validate Contracts | `veld check` (includes lint) |
| Generate | `veld generate` |
| Generate (Dry Run) | `veld generate --dry-run` |
| Check Generated Code Is Up To Date | `veld generate --check` |
| Setup (Wire Targets Into Apps) | `veld setup` |
| Watch (Generate On Change) | `veld generate --watch`, until you press stop |
| Export OpenAPI... | `veld export openapi -o FILE` (asks for the file) |
| Doctor | `veld doctor` |

## File | New | Veld File

Templates in `src/main/resources/fileTemplates/internal`: **Model**, **Enum**, **Error**,
**Service**, **veld.toml (single service)** and **veld.toml (workspace)**. The name you type
becomes the declaration name (or the file name for `veld.toml`: type `veld`).

## `veld.toml` schema

`src/main/resources/schemas/veld.toml.schema.json` is generated by `cargo xtask codegen` from the
config spec. `VeldTomlSchemaProviderFactory` (loaded only when the bundled JSON plugin is present)
maps it to every file named `veld.toml`, so a JetBrains IDE with the TOML plugin validates keys and
values and offers completion and documentation in that file. Without the TOML plugin the mapping is
inert: the file opens as plain text.

## Color settings and code style (what is intentionally not here)

v1 had its own PSI lexer, so it had a color settings page, a code style page, a brace matcher and a
commenter. Veld 2 has no PSI (the plugin is a thin client), so those are provided differently:

- **Colors.** Highlighting is the bundled TextMate grammar, and the IDE already lists its scopes
  under Settings | Editor | Color Scheme | TextMate, where each Veld scope can be recolored. LSP4IJ adds
  Settings | Editor | Color Scheme | Language Defaults semantic-token colors, which the language
  server's semantic tokens use. A separate `ColorSettingsPage` would need a `SyntaxHighlighter`
  with its own text attribute keys, which would duplicate the TextMate grammar and drift from it.
- **Code style.** Formatting is `veld fmt` through LSP (Reformat Code). It has no options by design
  (one canonical format, so formatting never differs between a developer and CI), so there are no
  settings for a code style page to hold.
- **Brace matching, commenting, folding** come from `language-configuration.json` in the TextMate
  bundle; **structure view, hover and documentation** come from LSP4IJ and `veld lsp`.

## Settings

Settings | Tools | Veld: **Path to veld**. Empty means look up `veld` on PATH. If the executable
cannot be found, a notification explains that and links to the setting. A change applies the next
time the language server starts (use the Language Servers tool window to restart it).

## Build and test

```bash
cd editors/jetbrains
./gradlew buildPlugin     # build/distributions/veld-jetbrains-2.0.0.zip
./gradlew test            # file type, server command, action registration and template tests, in a headless IDE
./gradlew verifyPlugin    # Plugin Verifier against IntelliJ IDEA 2024.3
./gradlew runIde          # a sandbox IDE with the plugin
```

The first run downloads the IDE (about 1 GB). The TextMate grammar is a generated copy: edit
`xtask/src/grammar.rs` and run `cargo xtask codegen`, never the JSON by hand.

## Manual verification

1. Build `veld` and put it on PATH, or note its path.
2. `./gradlew buildPlugin`, then in the IDE: Settings | Plugins | gear | Install Plugin from Disk,
   choose `build/distributions/veld-jetbrains-2.0.0.zip`, restart. (Or `./gradlew runIde`.)
3. Open `examples/hello` as a project and open a `.veld` file. You should see:
   - the Veld icon on the file and keywords, types and strings colored (TextMate);
   - the language server running in the Language Servers tool window (View | Tool Windows);
   - introduce a type error: a diagnostic underline appears; hover shows its code and message;
   - Ctrl+Click on a type name jumps to its declaration; Alt+F7 finds references;
   - Ctrl+Space completes; Shift+F6 renames across files; Reformat Code (Ctrl+Alt+L) formats.
4. Set Settings | Tools | Veld | Path to veld to a wrong path and restart the server: an error
   notification "Veld language server not started" appears with an "Open settings" action.
