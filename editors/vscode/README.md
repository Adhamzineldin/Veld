# Veld for VS Code

A thin client for the [Veld](https://github.com/Adhamzineldin/Veld) contract language. All language
features come from the language server that ships inside the `veld` binary (`veld lsp`):

- diagnostics for the whole project, with codes and related locations
- hover (docs, kind, signature, resolved type; method, path, statuses and errors for endpoints)
- go to definition (types, `use` imports, errors) and find references
- completion (keywords, HTTP methods, types with auto-import, annotations with argument snippets, enum variants after `= .`)
- outline, rename across files, formatting, semantic tokens

The TextMate grammar (`syntaxes/veld.tmLanguage.json`) is generated from the compiler's language
table with `cargo xtask codegen`. Do not edit it by hand.

## Requirements

Install Veld 2 and make sure `veld` is on your `PATH`, or set `veld.path`.

## Commands

Open the command palette and type `Veld`. Every command runs the `veld` CLI (see `veld.path`) in the
folder of the active file, or in the folder that holds `veld.toml`, and prints into the **Veld**
output channel. The status bar item shows the result of the last run; click it to validate.

| Command | Runs |
|---|---|
| Veld: Validate Contract | `veld check` (includes lint) |
| Veld: Generate Code | `veld generate` |
| Veld: Generate (Dry Run) | `veld generate --dry-run` |
| Veld: Check Generated Code Is Up To Date | `veld generate --check` |
| Veld: Setup (Wire Targets Into Apps) | `veld setup` |
| Veld: Export OpenAPI / Export... | `veld export <openapi|ir> -o FILE` |
| Veld: Watch (Generate On Change) | `veld generate --watch`, as a background task |
| Veld: Doctor | `veld doctor` |
| Veld: Restart Language Server, Show Output | |

The watch command is also a task (`"type": "veld", "command": "watch"` in `tasks.json`). Tasks use
the `$veld` problem matcher, which turns `error[E0205]: ...` and ` --> file:line:col` output into
entries in the Problems panel.

## Snippets

`snippets/veld.json` has contract snippets in v2 syntax: `model`, `enum`, `error`, `union`,
`service`, `get`, `post`, `put`, `patch`, `delete`, `sse`, `ws`, `crud`, field forms (`field?`,
`field[]`, `fieldmap`, `fielddef`), annotations (`@auth`, `@length`, `@example`, ...),
`use`, `usepkg` and `const`. `snippets/veld-toml.json` has `veld.toml` snippets (`veld-single`, `veld-service`, `veld-app`,
`veld-workspace`, `veld-node`, `veld-java`, `veld-typescript`, `veld-react`, `veld-plugin`,
`veld-dependency`, ...).

## `veld.toml` completion and validation

`schemas/veld.toml.schema.json` (generated by `cargo xtask codegen` from the config spec) is
registered with `tomlValidation`. Install the
[Even Better TOML](https://marketplace.visualstudio.com/items?itemName=tamasfe.even-better-toml)
extension to get completion, hover documentation and validation of `veld.toml` (keys,
`emitter` and `framework` values).

## Settings

| Setting | Default | Meaning |
|---|---|---|
| `veld.path` | `veld` | The executable used for `veld lsp` and every command |
| `veld.validateOnSave` | `true` | Run `veld check` when a .veld file is saved (status bar) |
| `veld.trace.server` | `off` | Trace the language server protocol |

## Development

```bash
npm install
npm run compile
```

The v1 extension re-implemented the language in TypeScript. That code was removed in 2.0 and
is preserved in git history.
